# Plan 2 — Audio completo · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que cualquier emisora del catálogo suene en DirectoRadio. Los streams `http` pasan por un proxy de audio propio y los HLS se reproducen con `hls.js`. Un mini-reproductor fijo sigue sonando al navegar, cada reproducción se cuenta y la portada pasa de forma progresiva al ranking propio de 30 días. También cierra los pendientes del plan 1 que tocan esta parte.

**Architecture:**
- **Proxy de audio:** es un servidor HTTP Node independiente (`src/proxy/`), que se arranca con `npm run proxy`. Recibe un identificador de emisora, busca su URL en la BD y retransmite el audio. Las conexiones salientes van con un `dispatcher` de undici que valida cada IP en el momento de conectar, así que se protege también contra DNS rebinding.
- **Web:** un `PlayerProvider` de cliente en el layout raíz mantiene un único `<audio>` y el mini-reproductor. Como el layout no se desmonta al navegar, la radio sigue sonando.
- **Reproducciones:** se registran con un route handler `POST /api/reproducciones`.
- **Ranking:** se calcula en SQL mezclando el ranking de Radio-Browser con el propio, según cuántas reproducciones haya en los últimos 30 días.

**Tech Stack:** el del plan 1 (Next.js 16 App Router, TypeScript, Tailwind 4, Drizzle + Postgres 17, Vitest 5, Playwright) más `undici` (dispatcher con validación de IP al conectar) y `hls.js`.

**Spec:** [docs/superpowers/specs/2026-11-04-directoradio-v1-design.md](../specs/2026-11-04-directoradio-v1-design.md). Este plan cubre las secciones 6.4 (ranking propio), 6.7 completa y 7 (proxy y su seguridad). El despliegue va en el **Plan 2b**, cuando existan cuentas y dominio.

**Evidencia previa (sondeo de 400 emisoras reales desde la red de desarrollo, 2026-11-05):**
- Composición: 140 `http`, 260 `https`, 45 HLS y 3 listas `.pls`/`.m3u`.
- Resultado: solo el 46 % respondió con audio en 8 s. El fallo dominante fue el timeout (182).
- Esos timeouts los provoca la red corporativa, no las emisoras. BBC, Europe 1, DLF, SWR y NRJ no devolvieron cabeceras ni con 30 s de margen.
- Consecuencia: la comprobación de salud y el proxy **no se pueden validar contra streams reales desde esta red**. Los tests usan un servidor de audio falso local, y `job:health` no se ejecuta contra la BD de desarrollo para ocultar emisoras.
- Enviar `User-Agent` arregló 3 fallos. Hay un caso de `application/octet-stream`.

## Global Constraints

- **Textos:** todo texto visible sale de `src/i18n/es-ES.ts` vía `t()` / `tn()`. Interfaz solo en `es-ES`.
- **Peticiones salientes a emisoras** (salud y proxy): llevan `User-Agent: DirectoRadio/0.1 (+https://directoradio.com)` e `Icy-MetaData: 0`.
- **Validación de URLs de emisora:** ninguna conexión saliente a una URL de emisora sin `isPublicHttpUrl` **y** sin el dispatcher fijado (`createPinnedDispatcher`), que rechaza IPs no públicas en el momento de conectar.
- **Entrada del proxy:** solo `GET /stream/{stationId}` con un UUID válido. Nunca recibe una URL. La emisora debe estar `activa`.
- **Respuestas aceptadas por el proxy:** `audio/*`, `application/ogg` o `application/octet-stream`. Cualquier otra, incluidas las de tipo `mpegurl` y las listas `.pls`/`.m3u`, devuelve `415`.
- **Límites del proxy:**
  - 3 conexiones simultáneas por IP de cliente (`429`) y 200 en total (`503`).
  - Timeout de cabeceras aguas arriba de 10 s (`504`).
  - Máximo 3 redirecciones, cada una revalidada.
- **Cabeceras de respuesta del proxy:**
  - `Content-Type` (copiado del origen)
  - `Cache-Control: no-store`
  - `Access-Control-Allow-Origin: {WEB_ORIGIN}`
  - `X-Content-Type-Options: nosniff`
  - No reenvía cookies ni cabeceras `icy-*`.
- **Variables de entorno nuevas:**
  - `AUDIO_PROXY_PORT` (por defecto `4100`)
  - `WEB_ORIGIN` (por defecto `http://localhost:3000`)
  - `NEXT_PUBLIC_AUDIO_PROXY_URL` (por defecto `http://localhost:4100`). Si está vacía, las emisoras `http` muestran `station.httpSoon` como hasta ahora.
- **Contador de reproducciones:** cuenta cuando el audio emite `playing` por primera vez. Una vez por emisora y sesión de navegador: `sessionId` es un UUID en `sessionStorage`, y la BD tiene la restricción única `(station_id, session_id)`.
- **Ranking de portada** (sustituye al del plan 1):
  - `P` = número de reproducciones de todas las emisoras en los últimos 30 días.
  - `w = min(1, P / 1000)` (`OWN_RANKING_FULL_AT = 1000`).
  - `score = w · own + (1 − w) · legacy`, donde:
    - `own = plays30d / max(plays30d)` (0 si el máximo es 0)
    - `legacy = (country_code = 'ES' ? 0.5 : 0) + 0.49 · ln(1 + clicks) / ln(1 + max(clicks))`
  - Orden: `score DESC`, `name ASC`, `slug ASC`. Mismos filtros que antes: `activa` y menos de 3 fallos de salud.
- **Plurales:**
  - «1 reproducción» y «{count} reproducciones»
  - «{avg} (1 valoración)» y «{avg} ({count} valoraciones)»
- **Etiquetas de género:** se mueven a `es-ES.ts` con claves `genre.{valor}`. Mismos textos: Pop, Electrónica, Rock, Jazz, Clásica, Variada, Noticias, Deportes, Generalista.

## Review Focus

1. **Intento de usar el proxy contra la red interna:** una emisora cuya URL resuelve a `10.x`, `127.x`, `::ffff:10.x`, 6to4 `2002:0a00::/24` o Teredo, o un DNS que primero responde con una IP pública y al conectar con una privada. En todos los casos el proxy responde `502` sin abrir conexión a esa IP. Lo cubren los tests de Task 3 `rejects private address at connect time` y `rejects transition ranges`.
2. **Oyente que cierra la pestaña a mitad de stream:** el proxy aborta la conexión con la emisora y libera el hueco del límite por IP. Test de Task 5 `aborts upstream when client disconnects`.
3. **Emisora que responde HTML o una lista `.pls` en vez de audio:** `415` y ningún byte reenviado. Test de Task 5 `rejects non-audio upstream`.
4. **Mismo usuario que pulsa play y pausa diez veces:** cuenta una sola reproducción. Test de Task 6 `counts once per session` y Task 8 `records play once per station per session`.
5. **Navegación mientras suena:** volver a la portada no corta el audio y el mini-reproductor sigue mostrando la emisora. Además, iniciar otra emisora sustituye a la anterior y no suenan dos a la vez. Test e2e de Task 9 y test de Task 8 `switching station releases previous stream`.

**Interfaces:**
- Consumes: `getDb`, `stations`, `isPublicHttpUrl`, `createPinnedDispatcher`, `STREAM_REQUEST_HEADERS`.
- Produces:
  - `class ConnectionLimiter { constructor(perIp: number, total: number); tryAcquire(ip: string): 'ok' | 'per-ip' | 'total'; release(ip: string): void; count(ip?: string): number }`.
  - `type ProxyDeps = { findStreamUrl(id: string): Promise<string | null>; fetchImpl: typeof fetch; isAllowedUrl(url: string): Promise<boolean>; limiter: ConnectionLimiter; webOrigin: string; headersTimeoutMs: number }`.
  - `createProxyHandler(deps: ProxyDeps): (req: IncomingMessage, res: ServerResponse) => Promise<void>`.
  - `findStreamUrl` por defecto: `SELECT stream_url FROM stations WHERE id = $1 AND status = 'activa'`.
  - `server.ts`: `http.createServer(createProxyHandler(defaults)).listen(AUDIO_PROXY_PORT)` y `GET /healthz` → `200 ok`.

Comportamiento de `createProxyHandler`:

| Situación | Respuesta |
|---|---|
| Método distinto de `GET` o `OPTIONS` | 405 |
| `OPTIONS` (preflight CORS) | 204 con `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods: GET` |
| Ruta que no es `/stream/{uuid}` | 404 |
| Emisora inexistente o no `activa` | 404 |
| Límite por IP (IP = `req.socket.remoteAddress`) | 429 |
| Límite global | 503 |
| URL no pública, redirección a URL no pública, `PinnedAddressError` o error de red | 502 |
| Sin cabeceras del origen en `headersTimeoutMs` (10000) | 504 |
| Origen sin 2xx | 502 |
| Origen 2xx con tipo no aceptado (Global Constraints) | 415 |
| Correcto | 200 con las cabeceras de Global Constraints y el cuerpo canalizado (`Readable.fromWeb(body).pipe(res)`) |

- Al cerrarse la petición del cliente (`req.on('close')`), aborta el fetch del origen y libera el limitador.
- El limitador se libera **una sola vez** en todos los caminos.
